# Сайт соревнования

## Overview

Статический Vite + vanilla JavaScript сайт Varna Local Cup. Leaflet показывает GPX. Node.js CLI использует официальный Garmin FIT SDK для подготовки результатов. GitHub Actions публикует готовую сборку на Pages.

## Why / Goals

Организатор ведёт данные локально и обновляет сайт коммитами. Посетителям доступны маршрут, высоты, участники и подтверждённые результаты. Авторизация, сервер и загрузка записей посетителями на сервер не нужны.

## Behavior

- Сбор и старт показаны отдельно. `meeting` задаёт время и координаты сбора, отметку на карте и переход к ней; `startApproximate` помечает ориентировочный старт. Эти поля не меняют GPX или хронометраж FIT.
- Данные проверяются до сборки. Неизвестные участники, повторные номера, неверные времена и устаревшие результаты останавливают сборку.
- Общий список сортируется по полному времени; официальные места отдельно в мужском и женском зачётах. Равные целые секунды дают места `1, 1, 3`. Велосипед на категорию не влияет.
- Средняя скорость = длина GPX / полное время, а не средняя скорость движения из FIT.
- Дистанция GPX — сумма расстояний по сфере. Набор и спуск — суммы изменений высоты без сглаживания; значения приблизительные.
- FIT должен иметь корректный CRC, тип activity и GPS с возрастающими отметками времени.
- Старт и финиш — ближайшие GPS-точки первого подходящего прохода через зоны радиусом 60 м. Промежуточные контрольные точки интерполируются по GPX через 500 м и проверяются последовательно с допуском 120 м. Обратный маршрут, пропуски контрольных точек или отсутствие финиша не допускаются в зачёт.
- Полное время — разница отметок финиша / старта. Остановки включаются. Результат округляется до секунды.
- Разрывы GPS свыше 30 с, скорость свыше 100 км/ч, разница длины более 8%, ручное время или несовпадение даты требуют пояснения при подтверждении.
- Ручные `--start` / `--finish` принимают ISO с часовым поясом и требуют GPS рядом с указанной зоной и временем.
- Подтверждение всегда выполняет организатор. По одному результату на участника; замена явная.

## Data & Files

- `data/event.json`: id, title, edition, location, date, startTime, startApproximate, meeting (`time`, `lat`, `lon`), timezone, status, ranking, routeFile, timing.
- `data/participants.json`: массив `{ id, bib, name, gender }`.
- `data/results.json`: подтверждённые записи с eventId, riderId, временем, отметками, distanceM, routeMatched, trace, courseHash, sourceHash, note, approvedAt и диагностикой.
- `public/route.gpx`: оригинал предоставленного маршрута. Поддерживается один непрерывный GPX trkseg.
- `src/generated/race.json`: проверенные данные для фронтенда, генерируются перед dev/build и не коммитятся.
- `activities/reviews/`: локальные JSON-черновики и HTML-отчёты с наложением треков. Не публикуются.
- `dist/`: готовый статический сайт, только этот каталог отправляется в Pages.

## Interfaces (CLI/API)

```text
npm run dev
npm run build
npm run preview
npm test
npm run import:fit -- --rider ID --file PATH [--start ISO] [--finish ISO] [--replace]
npm run approve -- --rider ID [--note TEXT] [--replace]
```

Импорт возвращает код 2 для неполного маршрута (отчёт сохраняется), 1 при ошибке, 0 при полном маршруте (замечания всё равно требуют проверки). API и база данных отсутствуют.

## Configuration

Node.js 22.12+. Настройки GPS — `event.timing`. Они входят в SHA-256 курса вместе с исходным GPX. Изменение маршрута или настроек после утверждения результата требует пересчёта: сохраните старые результаты отдельно, очистите `results.json` и переимпортируйте записи. Репозиторий GitHub: Pages source = GitHub Actions, ветка = main.

## Usage Examples

Полный рабочий процесс и примеры команд см. в [README](../README.md). Для нового заезда обновите id, date, edition и очистите результаты; история предыдущего заезда остаётся в Git. Архив нескольких заездов в интерфейсе пока не предусмотрен.

## Testing

`npm test` проверяет GPX, настоящий бинарный FIT, закодированный Garmin Encoder, остановки, разминку / заминку, неполный и обратный маршрут, ручное время, CRC, зачёты и ничьи. Сквозной тест запускает импорт и подтверждение в отдельном временном каталоге и проверяет защиту от дублей и смены курса. Синтетические записи не попадают в данные соревнования.

`npm run build` проверяет схему реальных данных и создаёт публикацию. Интерфейс проверяется в браузере на карте, фильтрах и узком экране.

## Risks / Migration Notes

GPS — приблизительный хронометраж, не судейская система. Ожидание у старта, многократный проезд стартовой зоны, редкая запись и ошибки координат требуют ручной проверки отметок. Проверка точек — эвристика: короткое срезание между контрольными точками может остаться незамеченным. HTML-отчёт позволяет сравнить треки перед подтверждением; исходные записи нужно сохранять локально.

Отображаемый трек прореживается до примерно 1200 точек после расчёта времени. В проверке участвуют все GPS-точки. При изменении имён сохраняйте id участника. Номера 1–4 назначены по порядку первоначального списка.

В Git и статический сайт попадает обрезанный трек утверждённого результата. Весь маршрут GPX и содержимое `public/` публичны. Исходные FIT и локальные черновики исключены из Git. Подложка требует доступа к [OpenStreetMap](https://www.openstreetmap.org/copyright). Чтение FIT основано на [официальном Garmin SDK](https://github.com/garmin/fit-javascript-sdk).
